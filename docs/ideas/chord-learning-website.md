# 和弦织网：声部流动创作器

## 问题陈述

**How Might We** 让音乐初学者直观、互动地理解和弦的本质——不仅是记住符号，而是真正"看见"和"听见"和弦在键盘上的形态、在乐曲中的过渡逻辑，以及它们如何组合成音乐语言？

## 推荐方向

"和弦织网：声部流动创作器"是一个以虚拟钢琴键盘和五线谱同步显示为核心的纯前端单页应用。用户从经典和弦进行模板出发，通过动画"看见"和弦之间的声部流动，自由替换和变形每一级和弦，在探索中学会用和弦讲故事。

之所以选择这个方向，是因为它填补了现有工具的市场空白：Chordify、UkuTabs 等工具是"查询型"的——告诉你这是什么和弦；音乐学院教材是"讲授型"的——用抽象符号讲解理论。而初学者的真实困境是"我想写一段和弦进行，但不知道怎么搭、为什么这样搭、还能怎么变"。这个工具从"句子"（和弦进行）而非"单词"（单个和弦）教起，用钢琴键盘的空间可视化和声部流动的动态动画，把乐理中最高级也最抽象的概念（voice leading）变成直觉。

纯前端静态站点的技术定位意味着零后端运维成本，可以快速迭代验证核心假设。

## 核心功能定义

| 功能模块 | 具体功能 | 优先级 |
|---------|---------|--------|
| **虚拟钢琴键盘** | 显示当前和弦在键盘上的按键位置；支持点击/触摸弹奏；高亮正在发声的音 | P0 |
| **五线谱同步显示** | 与键盘实时同步，显示当前和弦的音符在五线谱上的位置；播放时音符同步高亮 | P0 |
| **和弦进行模板库** | 内置 8 个经典模板（1-5-6-4、2-5-1、1-4-5、6-4-1-5 等），每个附带情绪标签（明亮/忧伤/神秘/紧张） | P0 |
| **声部流动动画** | 两个和弦切换时，动画显示每个音的移动路径——保留音静止、级进音平滑滑动、跳进音弧线跳跃 | P0 |
| **和弦替换器** | 点击进行中的任意一级，弹出可替换的变体菜单（三和弦→七和弦→挂留和弦→加九音等），实时试听并显示差异 | P0 |
| **符号解码器** | 悬浮在任何和弦符号上，弹出层显示其构成音、名称含义、情绪色彩（Cmaj7 = 大七和弦，色彩：梦幻、开放） | P1 |
| **创作模式** | 空白画布，用户自由拼接和弦，系统检测是否符合调性规则并给出提示（如"这个进行包含一个意外离调，听起来会有转折感"） | P1 |
| **解锁进阶** | 完成基础模板后渐进解锁：转位、借用和弦、副属和弦、调式互换等高级概念 | P1 |
| **速度/调性控制** | 调整播放速度、整体移调（适配用户嗓音或乐器） | P1 |

## 目标用户画像

### 主要用户：想成为创作者的入门者

- **特征**：会弹一点钢琴/键盘，能弹唱几首歌，想写自己的歌但看不懂复杂的和弦符号
- **痛点**：YouTube 教程零散不成体系，乐理书太抽象看不进去，现有工具只给答案不给原理
- **使用场景**：周末坐在 MIDI 键盘前打开网站，选一个"忧伤"标签的进行，听到声音后试着把其中一个和弦替换成七和弦，突然写出一段自己满意的旋律
- **成功标准**：能独立修改一个模板并进行，且能说出"我把这里换成属七和弦是因为想要一种悬而未决的感觉"

### 次要用户：音乐理论自学者

- **特征**：没有老师，纯自学，文字解释无法理解，需要"看见"音乐
- **痛点**：传统教材用"共同音保持、级进优先"等文字描述声部进行，缺乏直观感受
- **使用场景**：在学完基础三和弦后，用工具观察 C→Am 的过渡中哪些音在动、怎么动，从而真正理解 voice leading 规则

## 技术可行性分析

| 技术方案 | 说明 | 权衡 |
|---------|------|------|
| **框架**：React + TypeScript | 组件化 UI，状态管理清晰 | 学习成本适中，类型安全，生态丰富 |
| **音频**：Tone.js | Web Audio 的高级封装，支持合成、采样、音序器、和弦播放 | 比原生 Web Audio API 更易用；MVP 可用自带合成器，后续可接入 SoundFont 提升钢琴音色 |
| **五线谱渲染**：VexFlow | 专门的 JavaScript 乐谱渲染库，支持音符、和弦、高亮动画 | 与 React 集成需要包装组件，但功能成熟 |
| **动画**：Framer Motion + Canvas | 声部流动轨迹用 Canvas 绘制贝塞尔曲线，UI 过渡用 Framer | Canvas 动画性能可控，React 生态内 |
| **部署**：Vercel / GitHub Pages | 纯前端，静态部署零成本 | 无需后端运维，但用户数据仅限本地 |
| **存储**：localStorage | 保存用户解锁进度、自定义进行、偏好设置 | 换设备/清缓存会丢失，MVP 阶段足够 |

### 关键技术风险与应对

| 风险 | 影响 | 应对方案 |
|------|------|---------|
| 浏览器音频自动播放策略 | 首次加载无法出声，用户体验断裂 | 首次页面交互（点击/触摸）后再初始化 AudioContext，并给出明确提示 |
| Tone.js 合成器音质偏电子 | 不像真实钢琴，影响沉浸感 | MVP 接受合成器音质；P1 接入 Salamander 等开源钢琴 SoundFont |
| VexFlow 与 React 的同步 | 五线谱和键盘状态不同步 | 封装 VexFlow 为受控 React 组件，所有渲染通过单一状态驱动 |
| 移动端 Canvas 性能 | 动画在低端手机卡顿 | 提供"简化动画"开关；优先保证音频和交互，动画降级为即时切换 |

## MVP 范围

### 包含（必须验证核心假设）

- 虚拟钢琴键盘 + 五线谱同步显示一个基础和弦
- 3 个经典和弦进行模板（1-5-6-4、2-5-1、1-4-5）
- 三和弦到大三/小三/属七的替换菜单
- 声部流动动画（基础版：保留音高亮、级进音滑动）
- 悬浮和弦符号显示构成音
- 速度调节

### 不包含（后续迭代）

- 游戏化解锁系统
- 创作模式的调性检测提示
- 挂留和弦、加九音、六和弦等扩展替换
- 转位、副属和弦、借用和弦等高级概念
- 移调功能
- 用户自定义模板保存

## 明确不做（保持聚焦）

| 不做 | 原因 |
|------|------|
| 吉他/尤克里里指法 | 钢琴键盘是最直观的"音高=空间位置"映射；加入其他乐器会分散焦点且大幅增加维护成本 |
| 用户注册 / 云端保存 | 纯前端定位，localStorage 足够；后端会大幅增加开发和运维成本 |
| AI 自动配和弦 | 超出纯前端能力，且会破坏"学习"的本质——用户需要自己做决定才有收获 |
| 完整的乐理课程体系 | 不是在线课堂，是创作工具；乐理知识只在用户需要时以"工具提示"形式出现 |
| 真实乐器音频录制/导入 | Web Audio 的麦克风接入复杂度高，且偏离核心教学场景 |

## 待验证的关键假设

- [ ] **假设 1**：初学者真的能通过声部流动动画"直觉理解"过渡逻辑，而非仅觉得"好看"。**验证方式**：让 3-5 个目标用户试用，观察他们是否能不看文字解释就预测下一个和弦的音效；问卷询问"你觉得这个动画帮助你理解了什么"
- [ ] **假设 2**：和弦进行模板 + 替换器的组合能激发创作灵感，而非只是机械套用模板。**验证方式**：追踪用户是否在模板基础上做出至少一次"非默认"替换；访谈询问"你有没有因为尝试替换而想出新的旋律"
- [ ] **假设 3**：五线谱同步显示对初学者有辅助作用，而非增加认知负担。**验证方式**：A/B 测试（可开关五线谱），观察两组用户的任务完成率和满意度差异
- [ ] **假设 4**：纯前端静态站点的性能（音频延迟、动画帧率）足以支撑流畅体验。**验证方式**：在目标设备（中低端笔记本 + 手机）上进行性能测试，确保音频播放延迟 < 50ms，动画帧率 > 30fps
